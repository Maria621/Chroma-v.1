## Padrão de organização do código — revisão V4.8

A revisão V4.8 corrigiu arquivos que concentravam centenas de tags ou declarações em linhas únicas.

### Estrutura existente
- `*.html`: páginas institucionais independentes, com elementos `head`, `header`, `main` e `footer` explicitamente estruturados.
- `style.css`: folha de estilos base e componentes legados.
- `v31.css`: refinamentos responsivos e visuais das versões subsequentes; alterações futuras devem evitar novas sobreposições desnecessárias.
- `app.js`: interações de conteúdo, galeria e disponibilidade do formulário.
- `v31.js`: navegação desktop/mobile e ampliação de artes.
- `api/contato.js`: API de contato, sem configuração de envio enquanto e-mail, antispam e privacidade não forem homologados.
- `assets/`: imagens e logotipos preservados.

### Convenções
- Usar **2 espaços** por nível de indentação, UTF-8 e fim de linha LF.
- Manter um bloco HTML por linha, com aninhamento legível, sem minificar o código-fonte.
- Escrever regras CSS em blocos com propriedades em linhas separadas e respeitar as consultas responsivas existentes.
- Organizar comandos JavaScript, callbacks e funções com quebras de linha; priorizar funções pequenas e nomeadas em futuras revisões.
- Evitar CSS inline e não duplicar blocos de navegação ou rodapé em futuras alterações sem um plano de migração para componentes compartilhados.
- Não alterar ativos reais, regulamentos, endereços ou informações institucionais apenas para facilitar formatação.
- Antes de publicar: conferir links internos, `id`s, JS, responsividade, contraste, formulário e deployment por commit.

### Escopo e limites da V4.8
Esta revisão foi **de formatação**, sem introduzir framework, pipeline de build, componentes novos, alteração de conteúdo ou configuração de e-mail. A consolidação arquitetural do CSS legado e a extração de componentes HTML compartilhados continuam como melhorias futuras e exigem testes visuais completos.


## Auditoria de engenharia e UX — V4.9 (prévia)

O HTML continua pré-renderizado para hospedagem estática no Vercel. Para eliminar o problema de manutenção de cabeçalhos/rodapés copiados manualmente, os componentes compartilhados têm agora **fontes canônicas**:

- \`src/partials/header.html\`: cabeçalho e navegação. O script gera o estado visual da página atual e a variação escura/clara.
- \`src/partials/footer.html\`: rodapé compacto, com o retorno ao início local ajustado conforme a página.
- \`scripts/sync-layout.mjs\`: atualiza todas as páginas a partir das fontes canônicas ou verifica divergências sem modificar arquivos.
- \`scripts/qa.mjs\`: verifica estrutura de HTML, IDs, links, âncoras, imagens, botões, componentes compartilhados e sintaxe de JS.
- \`.github/workflows/quality.yml\`: executa QA automático na branch de revisão e em PRs destinados a \`main\`.

### Fluxo de trabalho

\`\`\`bash
npm run sync:layout  # após editar um componente compartilhado
npm run check:layout # confere se todas as páginas utilizam a fonte canônica
npm run check:js
npm test
\`\`\`

Este fluxo **não altera a renderização em tempo de execução**. Os arquivos HTML no repositório continuam prontos para deploy, sem bibliotecas extras no navegador.

## Revisão V5.0 — arquitetura CSS, UX e qualidade visual

- A imagem WebP que estava embutida como **153 mil caracteres Base64** em `style.css` foi extraída para `assets/interior-hero.webp`. A referência CSS continua apontando para o mesmo conteúdo visual, agora como recurso independente e armazenável em cache.
- `style.css` foi reduzido de aproximadamente 252,7 mil para 99,7 mil caracteres, sem remover os componentes utilizados nas páginas internas.
- A home foi reduzida de **12 para 10 seções**: a seção “Pessoas” repetia acompanhamento individual já explicado na metodologia e em Nossa Escola; a seção final de contato repetia chamadas disponíveis na navegação, no rodapé e na página Contato.
- O título principal foi encurtado e a altura do hero limitada para reduzir excesso de rolagem, preservando a composição azul e a fotografia conceitual identificada como ilustrativa.
- Foram adicionadas as dimensões intrínsecas das imagens AVIF/WebP já existentes nas páginas HTML. Isso permite que o navegador reserve proporção e reduz potenciais deslocamentos de layout.
- O ritmo vertical da home foi suavizado por ajustes nos espaçamentos base e da seção Novidades, sem alterar o conteúdo das demais páginas.
- O QA foi estendido para rejeitar imagens estáticas sem dimensões, arquivos CSS com raster Base64 extenso, recursos locais de CSS ausentes e regressões no número de seções da home.
